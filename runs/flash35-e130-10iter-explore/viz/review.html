Explore Run Review（實驗性）

  1. 先看「Review 總覽」表每輪改了什麼、分數多少、自動檢查有沒有過。點任一列會跳到那一輪。
  2. 點開那一輪的卡片看 Gemini 的假設、程式 diff、loss 曲線，以及這輪結果怎麼回饋給下一輪。
  3. 有疑問就留言在 diff 點行號針對那一行留言，或在卡片最下面選同意 / 懷疑 / 要多跑 seed。（留言只在分享連結版）
實驗性 explore run，不是主結果。主結果是 flash35-e130-10iter（47.27% → 57.73%）。這次只換了給 Gemini 的 prompt（--prompt-variant explore）：拿掉「minimal code change、一次只改一個想法、偏好短預算有效的改動」這類引導，改成列出可探索的方向（換 SSL 方法、改 encoder 架構），並告訴 Gemini 每輪實際花了幾分鐘、上限 60 分鐘。其他全部相同：gemini-3.5-flash、130 pretrain epoch、linear probe 100 epoch、seed 42、同一個 val split、epoch 與 optimizer 鎖定，另外每輪 GPU 記憶體上限 24 GB。
揭露：Gemini 免費方案多次回 503（high demand），失敗的輪次（沒有執行任何實驗）已刪除，所以 iter 編號跳過 5 與 8；原始紀錄有備份。這次用了 3 個 Google 帳號的免費 API key。iter 3 的提升有一大部分來自把 backbone 加寬 1.5 倍（寬度改回 1.0 倍的對照實驗只有 58.09%），之後的 best 也都是更大的模型，每輪耗時從 18 分鐘增加到 24–40 分鐘：epoch 固定，但模型容量與算力沒有固定。
